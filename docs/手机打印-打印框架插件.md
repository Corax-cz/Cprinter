# 手机直接打印（Android 打印框架插件）

前几个阶段解决的是「别人往这台手机打」：局域网 IPP 服务 + mDNS。
本文解决的是**反向**：手机自己怎么打印 —— 在 WPS、相册、Chrome、微信里
点「打印」，能直接看到这台打印机并出纸。

实现：`app/src/main/java/com/cawzen/printserver/androidprint/UsbPrintPlugin.kt`
（`android.printservice.PrintService` 子类）。

---

## 1. 为什么这条路比想象中短

Android 的 Print Spooler **总是先把应用内容渲染成 PDF**，再把一个只读文件描述符
交给打印服务。所以插件收到的东西和我们 IPP 服务收到的 PDF 完全同构，可以直接复用
`PdfPrint.print()` 这条已经验收过的管线 —— 不需要为它再写一套渲染。

对比一下三条入口与它们的输入格式：

| 入口 | 谁发起 | 收到的格式 | 处理方式 |
|---|---|---|---|
| App 内「打印自检 PDF」 | 本 App | PDF（自己生成） | `PdfPrint` |
| 局域网 IPP 服务 | 电脑 | PDF / PCL / PWG Raster | `PdfPrint` / `RawPrint` / `PwgRaster` |
| **打印框架插件** | **手机上的任意应用** | **PDF** | `PdfPrint` |

三者共用同一个 `UsbGate` 串行锁，不会互相踩到同一个 Bulk OUT 端点。

## 2. 三个必须踩过才知道的坑

### 2.1 元数据 XML 的属性既不带 `android:` 前缀，也不是短横线

`res/xml/printservice.xml` 由 `PrintServiceInfo` 用
`parser.getAttributeValue(null, "vendor")` 解析 —— 读的是**无命名空间**属性。

写成 `android:vendor` 能过编译（AAPT 恰好认这个属性名），运行时却是 null。

更麻烦的是属性名本身是**驼峰**：

```xml
<!-- 正确 -->
<print-service
    addPrintersActivity="com.cawzen.printserver.MainActivity"
    vendor="Cawzen" />

<!-- 编译通过、运行时读不到，dump 里该字段为空 -->
<print-service
    add-printers-activity="..."
    vendor="Cawzen" />
```

`addPrintersActivity` 只影响系统打印界面里「添加打印机」按钮的跳转目标，
不影响核心打印能力 —— 但写错了会让用户在打印设置里点按钮时毫无反应。

### 2.2 `onStartPrinterStateTracking` 不回应 = 打印机不可用

这是本次唯一一次真正的功能故障，现象很有欺骗性：

- 打印机在列表里正常显示，名称、描述都对
- 选中之后预览正常
- 但一按打印，界面变成「**该打印机目前无法使用**」

原因：系统在用户选中打印机后会回调 `onStartPrinterStateTracking()`，
插件必须在这时重新 `addPrinters(...)` 回应状态。空实现（我当时为了二分排查
把它注释掉了）会让 spooler 认为状态未知，直接判定不可用。

```kotlin
override fun onStartPrinterStateTracking(printerId: PrinterId) {
    if (printerId.localId != LOCAL_ID) return
    addPrinters(buildPrinters())   // 必须回应
}
```

**排查教训**：二分法去掉代码时，要区分「可选功能」和「协议握手」。
capabilities 属于前者（去掉只是少了分辨率选项），状态跟踪属于后者（去掉直接不可用）。

### 2.3 `PrintJob` 的每个方法都只能在主线程调用

这是本次唯一一次真正的崩溃，也是最难从现象推回原因的一个。

现象：作业入队日志打出来了，紧接着进程消失（`Process ... has died: fg TOP`），
`crash` buffer 里只有一句：

```
java.lang.IllegalAccessError: must be called from the main thread
    at android.printservice.PrintService.throwIfNotCalledOnMainThread
    at android.printservice.PrintJob.getInfo
    at UsbPrintPlugin.runJob(UsbPrintPlugin.kt:165)
```

`PrintJob` 的 `getInfo` / `getDocument` / `start` / `fail` / `complete` /
`setStatus` / `setProgress` **全部**带 `throwIfNotCalledOnMainThread()` 检查。
我按常规做法把整个作业丢进工作线程，第一行 `printJob.info` 就炸了。

**为什么特别难缠**：它抛的是 `IllegalAccessError`，属于 `Error` 不是 `Exception`，
落在 `catch (t: Throwable)` 之外（我确实写了 Throwable 兜底，但那一行在
`try` 块之前 —— 拿 info 是为了构造日志）。未捕获的 Error 直接让线程死亡，
系统随即 SIGKILL 整个进程。

正确做法：**主线程只做资料提取和状态回报，工作线程只做渲染和 USB 写**。

```kotlin
override fun onPrintJobQueued(printJob: FwPrintJob) {
    // 主线程：一次性取出全部所需信息
    val key = printJob.info.id?.toString() ?: "?"
    if (!printJob.isQueued) return
    if (!printJob.start()) return
    val attrs = printJob.info.attributes
    val pfd = printJob.document.data ?: return

    worker.execute { runJob(printJob, key, attrs, pfd) }   // 重活丢出去
}

// 工作线程里回报状态一律 post 回主线程
private fun failOnMain(printJob: FwPrintJob, msg: String) {
    main.post { runCatching { printJob.fail(msg) } }
}
```

### 2.4 取消只能靠显式检查，不能靠抛异常

`PdfPrint.print()` 内部有 `catch (t: Throwable)` 兜底（为了把任何异常都变成
可读的失败报告）。所以从 `onLog` 回调里抛 `CancelledByUser` 会被**误判成打印失败**，
用户看到的错误是「打印机出错」而不是「已取消」。

改成显式的 `shouldAbort: () -> Boolean` 参数，在**每页边界**检查一次。
不在半页处中断是有意的：写到一半停会留下不完整的 PCL 流，打印机会停在
「等待数据」状态，比多印一页更麻烦。

## 3. 声明给系统的能力

```kotlin
PrinterCapabilitiesInfo.Builder(printerId)
    .addMediaSize(ISO_A4, true)                       // 只吃 A4
    .addResolution(Resolution("res600", "600 dpi 细腻", 600, 600), true)
    .addResolution(Resolution("res300", "300 dpi 快",   300, 300), false)
    .setColorModes(COLOR_MODE_MONOCHROME, COLOR_MODE_MONOCHROME)
    .setDuplexModes(NONE or LONG_EDGE, NONE)
```

实测在系统打印界面的「选项」面板里正确呈现为：

```
颜色：黑白      方向：纵向
双面：无        页数：全部 1 页
```

用户在打印界面改的分辨率／双面会通过 `PrintAttributes` 传回插件
（`resolveOptions()`），优先级高于 App 内的全局设置 —— 用户在哪个界面做的选择，
就以那个为准。

---

## 4. 权限：为什么必须由前台拿

打印作业在后台线程触发，此时用户可能已经退出打印页。从后台
`UsbManager.requestPermission()` 弹出的对话框不保证可见，阻塞等待只会拖住队列。

所以：
- **插件只检查，不申请**。缺权限时 `printJob.fail()` 写入明确指引，用户能在
  系统打印队列里看到。
- **前台负责拿**。`MainActivity` 启动时自动申请一次（`LaunchedEffect(Unit)`），
  `openSystemPrint()` 在拉起打印界面之前也会再确认一次。

### 5.1 调试时容易误判的两件事

**① 首次使用会弹一个系统确认框**

第一次向某个打印服务提交作业时，系统会弹：

> 要使用"打印服务"吗？您的文档可能会通过一个或多个服务器发送至打印机。

这个框会拦住打印按钮的点击。自动化点击时表现为"点了没反应"，
容易误判成按钮不可用。授权一次后不再出现。

**② 打印机下拉列表压在状态栏上**

列表绘制在屏幕最顶部（y≈90–236），与 MIUI 的状态栏下拉手势区重叠。
`adb shell input tap` 注入的点按会被系统当成手势起点，表现为拉下通知栏 →
`PrintActivity` 失焦取消 → 界面消失。调试时用
`input keyevent 19/20/66`（方向键 + 确认）导航可以避开这个问题。
真人手指点按不受影响（系统能区分点击与下滑）。

## 6. 怎么用

1. 打开「打印服务器」App（会让系统授予 USB 权限）
2. 任意应用里点「打印」→ 打印机下拉框选「联想 LJ2600D」
3. 需要的话展开「选项」改分辨率 / 双面
4. 点右上角打印

打印机没插、没开机，或者被别的程序（如 Termux 里的打印服务）占用时，
作业会在系统打印队列里明确失败并给出原因，不会静默丢弃。
